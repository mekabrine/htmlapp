# HTMLApp — AI App Building Skill

HTMLApp is an iOS shell for creating, importing, editing, saving and launching small apps made with HTML, CSS and JavaScript. It supports iOS 16+; Apple Intelligence on-device features require compatible iOS 26+ devices. The user can take a self-contained HTML file generated by a subscription AI assistant (no API key required for the file creation) and import it using HTMLApp's Files interface or iOS Open In menu.

## Your job

When asked to make a new HTMLApp app, produce an **actual, working, complete HTML5 file** in a code artifact the user can save with the `.html` extension. Do not merely describe an app. Make the visuals distinctive for its purpose, with functional buttons, inputs, persistence, empty states and errors. Prefer a single standalone document containing inline CSS and JavaScript.

A subscription AI model working in its own chat creates or edits this file; HTMLApp itself does not automatically connect to that subscription or run the assistant's cloud account. To revise an app, ask for its existing HTML, edit it, and return the complete revised file unless the user requests patches.

## Host environment

HTMLApp runs saved HTML in WKWebView and may expose `window.HTMLAppNative` and `window.HTMLApp`. These are **not browser standards**; they are absent in Safari, normal websites and some previews. Check existence and availability, ask users before sensitive operations, and give an honest fallback. Supported capabilities differ by OS, device, permissions and signing/entitlements. Never invent methods: request the installed HTMLApp API catalog or inspect `HTMLAppNative.capabilities.list()` when available.

Examples of potential host integrations on supported builds include file and photo picking, document scanning, local app storage, structured SQLite data, widgets, notifications, location, reverse geocoding, mapped road speed-limit lookup, QR scanning, speech, Bluetooth LE, Core Image, PDF text inspection, maps, NFC, HealthKit, drawing, haptics, gamepad input and AI. Each needs its actual documented method and may require explicit per-saved-app permission. GPS provides coordinates and speed, NOT a street address or a posted speed limit. HealthKit/NFC/Apple Intelligence may not work under all signing configurations.

Use feature detection:
```js
const native = window.HTMLAppNative;
const hasFilePicker = !!native?.files?.pick;
if (!hasFilePicker) showMessage('Open this app inside HTMLApp to pick files.');
```
Do not silently access contacts, health, location, camera or microphone, and never assume a permission was granted. Catch rejections, handle cancellation, and offer retry.

## Short-prompt editing and semantic stability

When revising an existing HTMLApp from a very short prompt (for example "cleaner", "more native", "make stats better" or "do the same to history"), infer the smallest reversible change from the current app. First identify the relevant screen/component, existing storage keys, native methods, navigation and current design tokens. Preserve all unrelated behaviors. Avoid a full rewrite for a local change. A reference such as "do the same" should use the preceding accepted edit when available; do not guess destructive changes from vague instructions.

Use stable `data-forge-screen` or `data-screen` identifiers for major screens, `data-forge-id` for meaningful components, and `data-route` for named destinations. Keep them stable across edits. Reuse CSS design tokens to make simple changes localized. If storage identity changes, write an explicit idempotent data migration and retain legacy records.

## Offline vs online — critical

A self-contained HTML file **does not contain a server**. It can work offline for local UI, calculators, notes and some native device features. A cloud AI API, website backend, GitHub Actions build service, Discord webhook, Theos compiler or other remote process still needs a working network connection and an independently deployed server. Do not claim to compile iOS tweaks, generate binaries, deliver pushes or run a server using HTML/CSS/JS alone.

When code uses a relative endpoint such as `fetch('/api/build')`, this works only when the HTML is served from the website hosting that API. Imported into HTMLApp with a `file:` or sandbox origin, `/api/build` points at the local app origin rather than the original cloud server. **Ask the user for the exact hosted backend base URL. Never guess it or hardcode unverified endpoints.** Preferred choices:
1. Open the existing hosted website as a website app in HTMLApp, preserving same-origin API routes; or
2. With explicit user-supplied HTTPS endpoint and allowed CORS/permissions, use an absolute URL to call the backend.

For remote integrations show a setup screen and a clear online/offline status. Do not download, cache, or rewrite API routes as if they were static assets. Avoid caching secrets. Never expose tokens in a publicly shared HTML file.

## Runtime v2 backends

When server logic is needed, provide a complete Python source and v2 manifest in
an inert script tag: `<script type="application/json" id="htmlapp-backend-v2">`.
Its JSON contains `source` and `manifest`. Escape less-than characters inside
JSON as Unicode escapes. HTMLApp deploys and validates the bundle on save.
Use `HTMLAppNative.backend.request({path, method, body, session})` in the frontend.
The host supplies the public app key. Sensitive routes need resource sessions.
Use the runtime contract in the generation instructions for actual SDK methods,
limits, checks, migrations and API formats. Never invent SDK APIs or dependencies.
Encrypt locally with established authenticated cryptography when requested;
never send plaintext or decryption passphrases to the server. Public app keys
are not user authentication. Handle request failures visibly.

## Local devices and TV remotes

For a device remote, first identify the exact model or platform, verify its control protocol, and implement the actual command and pairing flow. Ask for the model if a missing detail changes which protocol works. A brand selector must choose a real implementation or say that the platform still needs a bridge. A reachability check and an accepted command do not prove the device acted on it.

In HTMLApp builds with LAN support, feature-detect `window.HTMLAppLocalNetwork?.isLocalURL(url)`. For private HTTP(S), use `HTMLAppLocalNetwork.fetch(url, options)`. For private WebSockets, the installed host routes supported local URLs through its wrapped `WebSocket`. Request access from an explicit Connect action. Distinguish network denial, pairing denial, timeouts, and an unsupported model. Do not use `HTMLAppNative.network.request` for private addresses: that API is for approved public HTTPS hosts. Outside HTMLApp, ordinary browser CORS and mixed-content restrictions apply. Never expose pairing tokens in exported HTML.

## Quality requirements

- Semantic, accessible HTML. Responsive on compact iPhone and iPad, respecting safe areas. Fixed page scale (no pinch/double-tap zoom): 16px minimum input text, accessible scalable typography, and actual responsive reflow.
- No document-level horizontal scrolling at ANY supported viewport or orientation. Only deliberately horizontal components (carousels, chip strips, graph timelines, wide table wrappers) may scroll sideways; mark them data-htmlapp-horizontal-scroll="true". Fix oversized elements rather than simply clipping them; use min-width:0, fluid media and wrap long strings.
- Actual working interactions: no dead buttons, fabricated server results, or fake completion.
- Persistent data only when needed; use localStorage/IndexedDB or real documented HTMLApp storage.
- Input validation, error recovery, cancellation, bounded requests and reasonable upload sizes.
- Distinctive visual design (purposeful typography, shapes, hierarchy, colors and motion); respect reduced motion.
- Avoid CDN dependencies for apps requested to work offline.
- Verify browser JavaScript syntax; test empty and populated states.
- Do not present speculative iOS APIs as supported without capability checks.

## How to deliver

Return the full HTML file with a clear filename, brief instructions for saving it and importing it into HTMLApp, a note identifying any online services, permissions or external server dependencies, and any hardware-only tests the user must perform. For edits, retain the user's data keys and functionality and explain necessary migrations.

## Native bridge discovery and safe cancellation

Recent HTMLApp runtimes expose `HTMLAppNative.protocolVersion`, `await HTMLAppNative.capabilities.has(method)`, `await HTMLAppNative.capabilities.describe(method)`, and `HTMLAppNative.permissions.status(name)` / `.request(name)`. Do not equate host permission with iOS system authorization. Recent builds return non-prompting `systemAuthorization` values where iOS exposes them (for example camera, microphone, location, photos and notifications); other frameworks may return `unknown`, `per_data_type` or `unavailable`. Never treat `capabilities.describe().available` as permission to read user data: check the saved-app host policy and request iOS consent when required. `HTMLAppNative.call(method, args, {signal})` can abandon a pending promise on AbortSignal; only currently cancellable native operations such as supported AI requests stop their underlying native task. Do not claim arbitrary operations are cancellable. Continue feature-detecting older runtimes.

## Native UI controls

Supported recent runtimes can use `HTMLAppNative.ui.alert({title,message,actions})`, `.menu(...)`, and `.datePicker({title,mode,value})` for real UIKit dialogs/pickers. Show them only in response to user intent; excessive modal requests are rate-limited. `HTMLAppNative.events.on(name, handler)` subscribes to existing `htmlapp:*` native events (and returns an unsubscribe function). Do not invent unimplemented native UI primitives.

For top-level navigation, match tab IDs to `data-htmlapp-screen` values and call `HTMLAppNative.screens.configure({items, selected})` when present. Use `data-htmlapp-go="settings"` for buttons and `screens.go("settings")` for code so the visible screen and native tab change together. Keep a working web navigation fallback. On iOS 26, feature-check `ui.glassShow` to add one decorative, touch-transparent native glass overlay with `ui.glassShow({x,y,width,height})` in viewport points. Update its bounds on layout changes, hide it with `ui.glassHide()` when leaving, and use `data-htmlapp-glass` for a web fallback.

For speech-to-text, use the documented `speech.listen` or `speech.recognize` API and expose a Stop button that calls its matching stop method. Saved apps use the speech engine selected in HTMLApp Settings. Whisper returns text after recording stops, so start the request without blocking the Stop button and await the original result afterward.

## On-device Apple Intelligence chat

Use `HTMLAppNative.ai.localAvailable()` to explain setup and `HTMLAppNative.ai.localComplete({messages, signal})` to answer a chat turn. This needs a compatible device on iOS 26+, a ready model, generated-app AI access enabled in HTMLApp Settings, and per-app AI consent. No provider key is needed. Keep the chat history in your app and send a short tail of up to 12 `{role, content}` messages with only `user` and `assistant` roles, ending in a user message. The encoded conversation must fit within 4 KB. Older hosts support `localComplete({prompt})`, which can receive a compact text transcript.

```js
const ai = window.HTMLAppNative?.ai;
if (!ai?.localAvailable || !ai?.localComplete) {
  showError("Open this app in a compatible HTMLApp build.");
} else {
  const status = await ai.localAvailable();
  if (!status.available) showError(status.reason);
  else {
    const { text } = await ai.localComplete({
      messages: [{ role: "user", content: "Give me three dinner ideas." }]
    });
    showReply(text);
  }
}
```

Handle errors, four requests per minute, cancellation, and repeated taps. Display model text as text, not injected HTML. Never silently switch to a configured cloud provider. Only offer cloud fallback as a separate, deliberate choice.

## Runtime helpers for real applications

Current HTMLApp releases may expose `HTMLAppData.collection(name)` (`put/get/remove/query/search/count`), `HTMLAppData.kv` (native portable appStorage), and `HTMLAppData.migrate(name, version, migrations)` for versioned, idempotent schema changes. `HTMLAppRuntime.runOperation(key, async ({signal}) => work, onStatus)` consolidates per-operation loading/error/cancel behavior; `cancelOperation(key)` and `onActive/onInactive/onBackground/onResume` assist cleanup. Use only after feature detection and never claim JavaScript keeps running while iOS suspends the host. Use `--htmlapp-text-scale` from the host for accessibility text scaling.

## Native audio recording, camera video and color selection

On supported installed builds, `HTMLAppNative.audio.record({maxDuration:60})` starts a foreground M4A recording after the app's microphone consent; max duration is 300 seconds. `audio.stopRecording()` produces an app-scoped `native-imports/audio/*.m4a` descriptor; `audio.cancelRecording()` discards it, `audio.levels()` provides metering, and `audio.play(url)` / `audio.pause()` / `audio.stop()` play native recordings. Listen for `HTMLAppNative.events.on('audio', callback)` for natural completion. Use `HTMLAppNative.share.present({url:file.url})` only after deliberate user action to export. Never claim background recording, or grant microphone permission silently.

`HTMLAppNative.video.capture({maxDuration:60})` opens native video recording after both saved-app camera and microphone authorization and returns an app-local `native-imports/videos/*.mov` descriptor, max 300 seconds and 150 MB. Export explicitly with the share sheet. `HTMLAppNative.ui.colorPicker({hex:"#3366FF",alpha:false})` opens a native color picker and returns `{hex,alpha,cancelled}` on dismissal. Always feature-detect these optional newer APIs and handle missing hardware.

## Native camera photo capture

On supporting devices, `HTMLAppNative.camera.capturePhoto({camera:'front'|'back',quality:0.85,maxDimension:2400})` opens a real camera UI only from the user's explicit action and returns a scoped `{url,name,mimeType,size,width,height}` file descriptor. `await fetch(photo.url)` is intercepted by the host's existing photo import bridge. Check permission, cancellation, and camera availability; never assume the camera can work in a preview or simulator.


## Interactive 3D and settings controls

For newly generated projects that need an interactive 3D object or settings
controls, opt into the package runtime with
`<meta name="htmlapp-runtime" content="package">`. Use bundled modules so the
project works offline. Avoid changing the runtime origin of an existing project
solely to restyle controls.

```html
<script type="module" src="/libraries/htmlapp/viewer.js"></script>
<script type="module" src="/libraries/htmlapp/controls.js"></script>
<link rel="stylesheet" href="/libraries/htmlapp/controls.css">
<htmlapp-viewer shape="box" color="#f59e33" label="Orange cube"></htmlapp-viewer>
<div class="ha-setting">
  <span class="ha-setting-label">Sound effects</span>
  <htmlapp-switch label="Sound effects" id="sound" checked></htmlapp-switch>
</div>
```

The viewer supports drag, pinch, and visible rotation, zoom and reset buttons.
For an existing local model, use `src` with its actual app-owned path. Use a
self-contained uncompressed glTF 2.0 binary (.glb) up to 16 MB.
Read or set the switch's `checked` and `disabled` properties and listen for
`change`. Persist settings explicitly when requested.


For grouped settings, a visible button can open real iOS controls using
`HTMLAppNative.ui.controls({title, fields})`. Supported field types are
`toggle` (boolean value), `slider` (numeric value, min/max, optional step),
`choice` (option ID value and options with id/title), and `text` (string value).
Give each field a unique id and title, and keep the form to at most 16 fields.
Apply returns `{cancelled:false, values}` keyed by field ID. Persist those values
in the project and leave them untouched when cancelled. Use the inline web
controls when the native bridge is unavailable or the workflow needs inline
editing. The system renders Liquid Glass styling on iOS 26 and later.
